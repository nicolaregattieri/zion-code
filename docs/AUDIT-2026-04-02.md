## PERFORMANCE AUDIT

### 1. Commit List Rendering

**Status: OK**

- `LazyVStack(spacing: 0)` correctly used (`GraphScreen.swift:217`)
- `ForEach(model.commits)` with stable `Identifiable` conformance + explicit `.id(commit.id)`
- `maxLaneCount` is a stored property on ViewModel (`RepositoryViewModel.swift:612`), recomputed only on `commits.didSet`
- `CommitRowView` receives all data as `let` properties -- no expensive per-row computations
- Avatar images cached with `NSCache`, async background fetch, nil returned immediately on miss

### 2. Commit Search

**Status: OK**

- 150ms debounce via `Task.sleep(nanoseconds: 150_000_000)` with cancellation (`GraphScreen.swift:114`)
- Results stored in `searchMatchIDs` (ordered) + `searchMatchIDSet` (O(1) lookup)
- 3-tier priority matching with `reserveCapacity` pre-allocation (`GraphScreen+Search.swift:66-71`)
- Navigation: `navigateSearch` just increments index -- O(1), no re-filtering

### 3. File Tree I/O

**Status: CONCERN**

- Async loading: `refreshFileTree()` and `loadChildrenIfNeeded()` correctly use `Task { }` -- OK
- Gitignore caching: TTL-based cache (10s) with per-repository storage -- OK
- **Flat file cache issue**: `allFlatFiles()` called during SwiftUI view body evaluation (QuickOpenOverlay, CodeScreen). When `isFlatFileCacheDirty` is true, it synchronously flattens the entire file tree on the main thread.
- **Impact**: Large repos (1000+ files) -- UI hitch when opening Quick Open after file tree changes
- **Fix**: Rebuild eagerly in `repositoryFiles.didSet` via background `Task`, or return stale cache while rebuilding async

### 4. Diff Parsing

**Status: CONCERN**

- `parseDiffHunks` splits raw diff and immediately converts every `Substring` to `String` via `.map(String.init)` -- N+1 allocations upfront
- Each diff line creates another `String` via `String(dropFirst())` -- 2N allocations total
- **Impact**: Noticeable on large diffs (1000+ lines). Not a blocker for typical diffs (<200 lines)
- **Fix**: Keep as `[Substring]` and only convert to `String` when storing in `DiffLine`

`buildPatch` / `buildPartialPatch`: Uses `[String].joined(separator:)` pattern. Creates intermediate strings but Swift's `joined()` is well-optimized. Runs on user-initiated staging actions. Acceptable.

### 5. Syntax Highlighting

**Status: CONCERN**

- Dirty tracking: Full system in place -- `lastHighlightedSignature`, `lastHighlightedTheme`, `lastHighlightedExtension` -- OK
- Regex caching: `regexCache: [String: NSRegularExpression]` prevents recompilation -- OK
- Large file protection: `shouldUseReducedHighlighting` skips for files above threshold -- OK
- **Issue**: `applyHighlighting()` is `@MainActor` and runs all regex matching synchronously. The 150ms debounce dispatches back to `DispatchQueue.main` -- debounces timing but doesn't offload work. Threshold (200K UTF-16) is high; files 50K-200K still block main thread.
- **Fix**: Offload regex computation to background thread, apply attributes on main thread. Lower threshold to ~100K.

### 6. Observable Overhead

**Status: CRITICAL**

- Excellent `@ObservationIgnored` discipline on 80+ properties (tasks, clients, caches, timers, file watchers)
- **Issue 1**: `refreshRepository` assigns ~20 properties sequentially (`currentBranch`, `headShortHash`, `branchInfos`, `branches`, `commits`, `uncommittedChanges`, etc.), each triggering separate observation notifications. Every view re-renders on every git refresh.
- **Issue 2**: 20+ editor/terminal/ntfy settings individually observable with `didSet` -> `UserDefaults`. Any preference change invalidates the entire ViewModel.
- **Issue 3**: `_aiKeyRevision` (line 341) exposed as observed property -- every AI key change triggers full observation chain.
- **Issue 4**: `currentFileDiff.didSet` performs O(n) string split synchronously for large diffs.
- **Fix**: Extract `EditorPreferences`, `TerminalConfiguration`, `NtfyConfiguration`, `AIFeatureFlags` into separate `@Observable` models. Batch `refreshRepository` assignments into a struct. Mark `_aiKeyRevision` as `@ObservationIgnored`.

### 7. TruncatingHStack Double Layout

**Status: CONCERN**

- `sizeThatFits()` and `placeSubviews()` both call `subviews.map { $0.sizeThatFits(.unspecified) }` -- redundant computation on every layout pass
- **Impact**: Rows with 5+ branch/tag decorations compute pill sizes twice per layout cycle
- **Fix**: Cache sizes from `sizeThatFits()` and reuse in `placeSubviews()`

## SECURITY REVIEW

### Findings

| # | Severity | Finding | File | Line(s) |
|---|----------|---------|------|---------|
| 1 | **CRITICAL** | `pkill -f` with string-interpolated port -- regex metachar injection if port source becomes untrusted | `CloudflareTunnelManager.swift` | 61-67 |
| 2 | **HIGH** | `sanitizeForJS` strips `+`/`/`/`=` from base64 keys, corrupting them. Keys injected into JS context silently fail | `RemoteAccessServer.swift` | 274-277 |
| 3 | **HIGH** | No route whitelist on remote access HTTP listener -- any path accepted and routed | `RemoteAccessServer.swift` | 412-416 |
| 4 | **MEDIUM** | Token passed as query parameter `?t=<token>` -- could leak in logs/history. Mitigated by Cloudflare tunnel. | `RemoteAccessServer.swift` | 475 |
| 5 | **MEDIUM** | `persistedToken` allows re-pairing without QR flow -- no rotation/revocation mechanism | `RemoteAccessServer.swift` | 487 |
| 6 | **MEDIUM** | Temp dir (`ZionTemp.directory`) doesn't check for symlink attacks before writing askpass scripts | `ZionTemp.swift` | 4-9 |
| 7 | **MEDIUM** | `revealFileInBrowser` constructs paths without resolving symlinks -- could traverse outside repo | `RepositoryViewModel+FileBrowser.swift` | 120-140 |
| 8 | **LOW** | No certificate pinning for AI provider API calls (URLSession.shared) | `AIClient+Helpers.swift` | 69-128 |
| 9 | **LOW** | Legacy (non-sandboxed) Keychain used due to no sandbox entitlement | `RemoteAccessEncryption.swift` | comment |

### Strengths

- Git commands use `Process()` with argument arrays (`["git"] + args`) -- no shell injection
- GIT_ASKPASS script passes credentials via environment variables, not script body
- All hosting credentials (GitHub/GitLab/Azure/Bitbucket PAT) stored via macOS Keychain
- Remote access: token-based pairing with TTL, rate limiting, connection limits, 64KB max body
- AI prompt injection defense: untrusted repo content wrapped in XML tags, suspicious pattern detection
- AES-256-GCM encryption for tunnel mode via CryptoKit

Strong design discipline. DesignSystem tokens are comprehensive (100+ tokens), `GlassCard` + `CardHeader` patterns consistently applied, interactive states well-layered on `CommitRowView`. Glassmorphism aesthetic is cohesive.

| Pattern | Count | Files |

### Key Issues

2. **7 raw `Color.white/black.opacity()`** in 4 files -- extract to `DesignSystem.Colors.*` tokens
3. **GeneralSettingsTab.swift:50** -- hardcoded `.linearGradient(colors: [.purple, .orange])` instead of ZionMode tokens

**MEDIUM**:
4. **SidebarView.swift:77,84** -- `.spring(duration: 0.3, bounce: 0.1)` instead of `DesignSystem.Motion.*`
5. **StatusBar.swift** -- 2 hardcoded animation durations, badge pills lack hover states
6. **Settings screens** -- `SecureField` no visible focus border, QR code missing `accessibilityLabel`
7. **QuickOpenOverlay** -- hardcoded `maxHeight: 400`, `width: 500`

**LOW**:
8. Portuguese L10n keys used as identifiers (legacy pattern, works but harder to maintain)
9. `Text("Zion Mode")` in GeneralSettingsTab not wrapped in `L10n()`
